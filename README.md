# NTVI — 四个工具共享的纪律

> **这份文件存在的理由，是它自己第一条纪律的失效方式。**
>
> 「一律像素风」这条最早写在 2026-10-06，原文是：
> **「两个工具的一切美术资源与界面，一律用像素风。」** —— 那时这个家族只有 **Nanodesu 与 Torikago**。
>
> 后来 **Volcano Separator** 与 **Ichiwatashi** 加入。**而没有任何东西会因此变红**：
> 两份各自手维护的副本一起变旧，四个仓库里有两个根本没有这条。
>
> **所以规则现在只写一份，放在这里。四个工具各留一句与一个指针。**

| 工具 | 仓库 | 是什么 | 有窗口吗 |
|---|---|---|---|
| **N**anodesu | [`Nesarf/Nanodesu`](https://github.com/Nesarf/Nanodesu) | PyInstaller 单文件可执行文件的解包与重打包（**只用标准库**） | 无，纯 CLI |
| **T**orikago | [`Nesarf/Torikago`](https://github.com/Nesarf/Torikago) | 未知可执行文件的隔离静态分诊，**从不执行目标** | 无，纯 CLI |
| **V**olcano Separator | [`Nesarf/volcano-separator`](https://github.com/Nesarf/volcano-separator) | 把 uv / Hindsight daemon / PostgreSQL 从一条脆弱链路里拆出来 | **11 个窗口脚本 —— 四边里唯一会开窗的** |
| **I**chiwatashi | [`Nesarf/Ichiwatashi`](https://github.com/Nesarf/Ichiwatashi) | 像素画的确定性测量与参数化构建 | 无，纯 CLI |

**四个工具互相独立、不共享代码。** 它们共享的是**纪律**，而纪律是这里唯一的东西 ——
这份仓库里没有代码、没有依赖、也不会有一个工具在运行期读它。

**而目录名与包名现在一致了。** Torikago 的代码仓目录一度还叫 `triage` —— 包名、命令名、远端仓库都
改成了 torikago，**只剩本地路径没动**，于是同一棵树在四个地方有三个名字，读到的人会以为它们是两件事。
现在目录也叫 `Torikago`，与被改过的六处引用一起（本仓库一处、Ichiwatashi 的跨仓库检查器四处、
一个研究项目一处）。

**这份文件按四件事组织：** ① 美术一律像素风 · ② 资源都出自 Ichiwatashi ·
③ Ichiwatashi 自己的产出 · ④ volcano 的窗口做到哪一步。最后 §五 说这份文件怎么维护。

---

## 一、美术与 UI：一律像素风（含窗口）

**四个工具都要有图形窗口，而四个工具的一切美术资源与界面一律用像素风。**
「界面」包括**窗口本身的设计** —— 不只是窗口里画的东西。

**⚠ 这条纪律的目的就是那些窗口，而我一度把它读窄了。** 原文（2026-10-06）写的是
**「两个工具的一切美术资源与界面，一律用像素风」**，而当时四边里**只有 volcano 有窗口**，
所以我把它当成了「约束已存在的东西」。**它是意图**：

| 工具 | 它的窗口是什么 | 为什么 |
|---|---|---|
| **Nanodesu** | **安防软件该有的窗口** | 它是安防类工具，而安防软件有它自己的界面语言：扫描进度、条目清单、可信度、拒绝理由 |
| **Torikago** | **安防软件该有的窗口** | 同上 —— 分诊的结论、指标、IOC，摆在一屏上给人看 |
| **Ichiwatashi** | **美术工具的窗口** | **它本身就是美术工具，没有窗口不成立**：调色板、画布、判据读数、预览都要看得见 |
| **Volcano Separator** | 进程羁押与活动可视 | 已有 `chamber` / `detain` 等 11 个窗口脚本 —— **而它的复杂度反而是四边里最低的** |

**而「都要开窗」触发了一件比窗口本身更值钱的事**：**四个窗口会需要同一套像素层** ——
位图字体、调色板、面板布局。**如果三边各造一套，就会得到四套 5×7 字体、四种画法、
而没有任何东西会变红** —— 那正是 §二 存在的理由。**所以共享的像素层是一个资源，而资源出自 Ichiwatashi。**

**而它已经迈出第一步，并且那一步走完了**：`ichiwatashi assets/font5x7.txt` 是那套共享字体的源，
`ichiwatashi font --format powershell` 产出 volcano 读的那种表。
**88 个字形，覆盖一个英文界面需要的全部字符** —— 字母（含 26 个小写）· 数字 · 标点 · 空格 ——
而这一点由 `ichiwatashi font --check` 报告，**它报的是缺什么**，不是「解析成功」。

**而那两个缺口是它自己报出来的**：加进去之前它说 `'` `#` 与全部小写都缺。
**`#` 那一个还撞出一个真冲突** —— `#` 既是注释标记又是字形，所以加进去之后字体仍然报它缺失；
**TAB 决定区别**（`#` 后跟 TAB 是字形，否则是注释）。

**所以「共享像素层」的第一件已经不是欠账了**；剩下的是**调色板与面板布局**，以及
**「怎么画出真像素」这一层** —— 后者目前只在 Volcano 被解决过，而那条路是 PowerShell 的。

**为什么是硬要求而不是偏好**：它同时服务三件四个工具都已经写下的事 ——

| 服务的那件事 | 怎么服务 |
|---|---|
| **可审计** | 像素图的生成过程可复现、无隐藏层、无第三方素材痕迹；**矢量 / 3D 管线会把来源弄糊** |
| **可携带** | 工具本身是「复制一个脚本就能用」；像素资源小、无依赖、无渲染栈 |
| **不淡化「ハメ」** | 像素风对成人向**是加分而不是收敛** —— 它允许更直白的表达，同时保持「这是自己画的」 |

**适用面**：图标 · 启动画面 · 帮助插图 · 报告里的图形 · **窗口设计本身** · 任何 UI。
**没有例外**（「就这一张矢量」也不行 —— **例外会让风格分家，而分家之后没人记得当初的界线在哪**）。

**而这条纪律在四个工具之间的落点不同 —— 这一点必须说清。**
规则的强度一样，但它落在的东西不一样；**假装它们相同，正是这条纪律第一次漂移的原因。**

| 工具 | 这条落在什么上 | 窗口现状 |
|---|---|---|
| **Nanodesu** | 一旦有 UI 或插图，只能是像素风 | **零 UI 代码** —— 未开始 |
| **Torikago** | 同上 | **零 UI 代码** —— 未开始 |
| **Volcano** | **已落地**：`bin/pixelfont.ps1` 自绘 5×7 位图字形，`bin/*.ps1` 的窗口用 `SetPixel` 画 | **11 个窗口脚本** —— 唯一在跑的 |
| **Ichiwatashi** | 它**测量**像素画，所以这条有两层：**对象**（只收像素画，`corpus/POLICY.md` 的三道门）与**自己产出的东西**（见 §三） | **零 UI 代码** —— 未开始 |

## 二、资源从哪来：**都出自 Ichiwatashi**

**四个工具的一切美术资源，都由 Ichiwatashi 生产。**

这条是 §一 的**执行方式**，不是另加的一条规矩 —— 「一律像素风」说了**是什么**，这一条说**从哪来**。
**而它按资源最终属于谁分两种，两种都成立：**

| 资源种类 | 它最终在谁那里 | 例子 |
|---|---|---|
| **给别处的资源** | 嵌进**用它的那个工具**的仓库 | volcano 的 5×7 位图字形；将来 Nanodesu / Torikago 的图标 |
| **给自己的产出** | 留在 **Ichiwatashi 自己**的仓库 | 判据报告里的对比图、预览图（见 §三） |

### 而它与「每个工具自包含」不冲突，因为这是两件不同的事

**⚠ 这一点我读错过一次，记在这里免得它回来**：家族里另有一条纪律说
**每个工具的像素层是自己的** —— volcano 的窗口不依赖别的项目，理由是
「一个以『不依赖任何东西』为价值的看门狗，不能依赖某样东西」。

**那条约束的是运行期依赖，不是来源。** 两句话同时成立：

| 层面 | 规则 |
|---|---|
| **来源** | 所有资源由 Ichiwatashi 生产 —— 它有形状工具、有调色板工具、有判据。**一处生产，四处一致** |
| **依赖** | 每个工具把产出**嵌进自己的仓库** —— 运行期不读别的项目、不装别的项目。**看门狗仍然谁都不依赖** |
| **可复现** | 配方（形状脚本 / 字形定义）留在 Ichiwatashi —— 产出可以重新生成，**而重新生成时会经过判据** |

**所以「复制一个脚本就能用」那条理由仍然成立**：复制的是**嵌入后的产出**，不是对另一个仓库的引用。

### 而这条规则**已经有一个 1:1 的检验，而它通过了**

`volcano-separator` 需要一套 5×7 位图字体，而它**在这条规则存在之前**手工写过一份。
所以它是对这条规则唯一可以**对着已经在用的东西**检验的场合：

| 检验（`ichiwatashi/tools/probe_font_from_ichiwatashi.py`） | 结果 |
|---|---|
| volcano 的 60 个字形，经 Ichiwatashi 的类型再产出 | **59 个逐字节复现** · **1 个被拒绝** |
| 那个被拒的 | **`/` 的第 5 行是 32，而五列只到 31** —— **volcano 的一处已记录缺陷，而 Ichiwatashi 的类型挡下了它** |
| 字形画成 `#`/`.` 再产出 | 与十六进制**完全相同**（同一个数据的两种写法） |
| Ichiwatashi 自己画的字形 | 产出**符合 volcano 的格式**，可直接粘贴 |

**所以这条规则不是愿望 —— 它有一个精确到字节的检验，而它通过了，只在上游有缺陷的那一处停下。**
**而那正是应该发生的行为：坏数据被拒绝，不被重新编码。**

## 三、Ichiwatashi 自己的产出：这条纪律在它身上原本是空的

**2026-10-12 定**：Ichiwatashi 的**产出**（报告插图、对比图、预览图）**也一律像素风**。

**为什么它需要单独说**：它是四边里唯一**自己不画任何东西**的工具 ——
它不画窗口、不做 UI，它的对象是**别人的**像素画。
所以「一律像素风」在它身上**原本是空的**，而**空规则和没有规则长得一样**，区别只在于前者会让人以为已经覆盖了。

**而 §二 给了它一个另三个都没有的位置**：**它是资源的生产者。**
所以它的产出侧不是一个附加项，而是**全家族的前提** —— 另三个要加美术时，得先有产能。

| 层 | 状态 |
|---|---|
| **对象侧**：只收像素画 | **已落地** —— `corpus/POLICY.md` 的三道门，每条实测挡得住 |
| **给别处的资源**：字形一类的位图数据 | **已落地** —— `ichiwatashi/font.py`，由 §二 那个探针逐字节验证 |
| **给自己仓库的产出**：报告插图与预览图 | **未做** —— 见 Ichiwatashi `TODO.md` 的「一、未做 · 产出」 |

## 四、Volcano 的窗口：这条纪律做到哪一步，以及它的界限

**它自己的注释里写着这个界限，而那句话值得抄在这里**：

> `# Style: pixel art, as a standing constraint for everything this project grows. What that means here`
> `# is honest and limited: PowerShell 5.1's WinForms text is antialiased, so this is pixel-art`
> `# [palette and panels] not pixel *rendering*. A real pixel-art layer would have to draw glyphs`
> `# itself. Saying otherwise [...]`

**而它正是这么做的**：`pixelfont.ps1` **自己画字形**（每行一个十六进制数字，bit 4 是最左），
用 `SetPixel` 落像素 —— **因为 GDI+ 提供的每一个绘图原语都会平滑，只有 `SetPixel` 不会。**

**而这条路上踩过的坑也记着**：字形表里有两处已知数据缺陷 ——
`Q` 被一个**渲染器读不到的十六进制数字**截断（十六位而只读前十四位），
`/` 的第 5 行设了**五列之外的 bit 5**。
它们**被测试钉住**（改动即红）而**不被擅自修** —— **两处都是画本身，修法是设计选择，不是推导。**

## 五、这份文件本身怎么维护

**规则只在这里写。四个仓库各留一句与一个指针，不复制正文。**

| 要做的事 | 怎么做 |
|---|---|
| **改规则** | 改这里，然后看四个仓库要不要跟 |
| **加工具** | 上面第一张表加一行，并在它的仓库里加那个指针 —— **这正是第一次漂移的成因，所以它是加工具的一部分，不是可选项** |
| **发现不一致** | 以这份文件为准，把仓库改成它；**如果仓库是对的、这份是旧的，那就改这份** |

**而这份文件不承诺它自己是完整的。** 它记录的是**已经定下的**纪律；
四条之外还有各仓库自己的规矩（`Torikago/TODO.md` §零 的关系定位、
`nanodesu-release/TODO.md` §零之二 的开发标准、`volcano-separator/DESIGN-enforcement.md` 的规则表），
**那些仍在各自的仓库里，而它们要不要上移到这里是另一件事** ——
**在这件事定下来之前，别把它们当成本文件的空缺。**
